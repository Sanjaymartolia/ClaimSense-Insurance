# ADR-0002: Where the synthetic starter data pack lives

**Status:** proposed
**Owner / layers:** Domain & Product (data) with Knowledge & Memory (ingestion), Eval & Red-Team — L4–L5, L13, L15
**Date:** 2026-10-28

## Context
The team's starter pack (`ClaimSense-main_v2`) shipped policy PDFs, synthetic claims with gold
worksheets (20 dev + 60 held-out), a tariff grid, red-team cases and a clause-extraction /
knowledge-base pipeline. Its layout (`data/policies/`, `data/claims/{development,heldout}/`,
`src/ingestion/` run as scripts) predates this repo's `src/claimsense/` package and the rules in
`CLAUDE.md`: held-out cases live outside the repo, and gold answers must never reach prompts or
tools.

## Options considered
A. Copy the pack verbatim. Fast, but it puts held-out gold in the repo, leaves dev gold beside
   agent-readable data, and keeps `sys.path` hacks.
B. Split by role and audience (chosen). Agent-facing inputs go in `data/`, scored material goes in
   `eval/`, held-out data goes outside the repo, and code moves into the package.

## Decision
| Starter pack | Here | Notes |
|---|---|---|
| `data/policies/new_india/` | `data/policy/new_india/` | 6 PDFs + manifest; hashes checked by a test |
| `data/tariffs/synthetic_tariffs.csv` | `data/tariffs/` | flag unusual prices only, never decide coverage |
| `data/processed/*` | `data/processed/` | regenerated by `extract_policy_clauses`; byte-identical to the pack |
| `data/knowledge_base/*` | `data/knowledge_base/` | regenerated by `build_policy_knowledge_base`; JSONL byte-identical |
| `data/claims/development/` | `eval/golden_dev/` | claims + gold worksheets; gold stays out of the agent data path |
| `data/redteam/attacks.jsonl` | `eval/redteam/` | |
| `data/claims/heldout/` | `../claimsense-heldout/` | **not in repo**; moved by a human, never read by Claude |
| `src/ingestion/*.py` | `src/claimsense/ingestion/` | run with `python -m claimsense.ingestion.<module>` |
| `tests/*.py` | `tests/ingestion/`, `tests/test_dataset_integrity.py` | held-out count check removed |

Not carried over: the `build-policy-knowledge-base` workflow (it pushed bot commits straight to a
`dev` branch, bypassing PR review; the existing `ci` workflow now runs the ingestion tests), the
placeholder `policy_clauses.jsonl` (superseded by `contracts/policy.py`), `src/README.md` (superseded
by `CLAUDE.md`), and `.DS_Store` files. `pypdf` joins the `dev` extra so CI can run the ingestion tests.

## Consequences
- **Contract gap (needs a 2-role PR):** the pack's claim JSON does not match
  `contracts.claim.Claim`. Money is integer `*_inr`, bill-line categories use names such as
  `room_rent`, and `policy`, `hospital` and `hospitalisation` are nested objects. Lines carry
  `room_linked` and `potentially_payable` flags. Either add an adapter in `ingestion/` or extend the
  contract. Until then, nothing validates these claims against `Claim`.
- Gold worksheets and the demo ruleset (`data/README.md`) are **not authoritative**: verify them
  against the policy wording before `calc/` hand-worked tests (T15) rely on them.
- `co_pay_rate` is a JSON float (`0.05`); parse with `Decimal(str(x))` in `calc/`.
- Knowledge-base clause records do not yet match `contracts.policy.Clause` either (`record_id` /
  `source_text` vs `clause_id` / `text`, no `effective_date`). That is a retrieval-side mapping.
